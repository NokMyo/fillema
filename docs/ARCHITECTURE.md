# Fillema v0.1 구조

## 원칙

1. UI 스레드는 파일 분석·변환·렌더링을 기다리지 않는다.
2. 편집 정보와 원본 미디어를 분리한다.
3. 미리보기 품질은 낮출 수 있지만 최종 처리 정밀도는 낮추지 않는다.
4. 외부 GUI 프레임워크 없이 운영체제 기능을 우선 사용한다.

## 계층

| 계층 | 역할 |
|---|---|
| Win32 UI | 미디어, 미리보기, 타임라인, 자동 속성 패널 |
| Project Model | 미디어 위치, 컷, 색감, 텍스트, 오디오, 출력 설정 |
| Preview Player | Windows Media Foundation 기반 경량 재생 |
| Adaptive Workers | 분석, 성능용 편집본, 정확 색감 프레임, 출력 작업 분리 |
| FFmpeg Planner | 검증된 디코딩·필터·오디오·인코딩 명령 생성 |

## 색 처리

`ColorGrade`는 원본을 건드리지 않는 편집 수치만 저장합니다. 출력 시 다음 순서로 FFmpeg 필터 그래프를 만듭니다.

1. 노출
2. 블랙·그림자·중간톤·하이라이트·화이트 커브
3. 대비·채도
4. 색온도·틴트·Shadow/Midtone/Highlight RGB 균형
5. Film Look
6. Grain·Vignette·Letterbox
7. 텍스트

정지 미리보기와 최종 출력이 같은 `BuildColorFilter` 함수를 사용하므로 두 경로의 색 처리 규칙이 갈라지지 않습니다.

## Adaptive Editing 기준

| 상황 | 자동 선택 |
|---|---|
| 2코어 이하 또는 메모리 6GB 미만 | 360p, 작업 스레드 1개, 무거운 미리보기 효과 지연 |
| 4코어 이하 또는 메모리 10GB 미만 | 540p 균형 미리보기 |
| 4K/H.265 | 백그라운드 성능용 편집본 |
| 그 이상 | 720p 고품질 미리보기 |

사용자가 품질·균형·속도 우선 모드를 직접 고르면 자동 판단보다 우선합니다.

## 프로젝트 파일

`.fillema`는 UTF-8 JSON입니다. 원본 파일을 복사하지 않고 다음 정보만 저장합니다.

- 미디어와 성능용 편집본 경로
- 컷 입출점과 순서
- 색감·속도·오디오·텍스트 수치
- 출력 설정

임시 파일에 먼저 쓴 뒤 교체해 저장 도중 손상 가능성을 줄입니다. 30초마다 별도 `.autosave.fillema` 복구본을 갱신합니다.

## 다음 구조 확장

1.x에서도 UI와 미디어 엔진의 경계를 유지합니다. 복수 트랙이나 GPU 색처리가 들어가더라도 `Project`와 FFmpeg 계획 계층을 교체하지 않고, 재생 엔진만 확장할 수 있게 구성했습니다.
